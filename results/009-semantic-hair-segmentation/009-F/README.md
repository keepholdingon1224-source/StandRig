## F0　素材2で近位候補を指定した診断

正解根元に最も近い有効な009-E候補を選んだ。左・右の候補誤差は28.18、27.66 px。009-Eのペアとして適格だが首位に選ばれず、座標変更と画素変更の効果も異なった。結論は**候補順位と子孫帰属の組み合わせ**。近位候補が存在するだけでは正しい可動領域を得られない。

## 共通規則と工程別評価

F1は顔領域から求めた楕円を最後に出た点から遠位端までの中心線を比較する。長さ、太さ、直線性、可視支持率で独立した2経路を選び、その下流部分を可視髪に投影する。F2は遠位領域から独立に、009-Eの妥当性制約を通過した候補をクラスタ単位で比較する。頭部との位置関係、くびれ、流れ、近位性、局所エッジを用いた。左右が顔中心をまたぐという共通の仮定を置いたため、両方の結び目が顔の同側に投影される構図は未検証。

F3は経路長、原画の勾配、補完髪からの逸脱、髪幅の変化を辺コストとし、左右の接続コスト合計が最小になる対応を選ぶ。中心線周辺を髪幅の範囲で拡張し、強いエッジ・顔・対側の既存領域を越えず到達できる可視髪のみを追加した。可視所有者とスカートはC2-Cに固定した。

F2が両素材で選んだ根元は009-Cと同じ。F1の遠位領域だけで素材1の適合率は低下した。F3は素材1で左4,785・右1,377画素を追加したが、どちらのRecallもF1から改善せず、追加分は全てFPだった。素材2ではF3が左を改善した一方で右を悪化させた。素材2は候補ペアのスコア差が0.025を下回りフォールバック。素材1では発動せず、安定した過抽出を安全層で検知できなかった。

素材2の正式根元誤差は左61.47／右43.19 px、正解根元を中心とする半径32 pxの窓IoUは左右とも0.0000。いずれも009-Eから変化なし。安全判定前の窓IoUは左0.1586／右0.1329。正式予測の手動座標指定・マスク修正・素材別設定・素材別後処理は全て0件。

## 再現と保護

既存venvでCPU実行。実行順は experiments/009-f の integrity.py start、diagnose.py、predict.py、evaluate.py、integrity.py end。正式推定コードのSHA-256をF0時点で記録した。prediction-lock.jsonにコード、共通定数を含む実装、入力、全36枚の予測、各工程の選択ログを固定した。独立評価ではそれらを再照合した後に基準マスクを読み込む。metrics.jsonとablations.csvに数値、error-galleryにTP（緑）・FP（赤）・FN（青）および根元・毛先拡大を収録。
