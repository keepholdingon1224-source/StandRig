# 009-A external diagnostic wrapper
Copy the contents of this directory to the experiment work directory, alongside StandRig and the pinned see-through checkout. The venv is .venv-009. Use the pinned requirements from the runbook and run pip from the see-through root to resolve its editable packages.
1. Create run-nf4-preflight, save nvidia-smi, then set HF_HOME to the work directory's hf folder. Run resolve.py and weights.py. Hashes and provenance are in verified-files.json.
2. Confirm the UUID in measure.py against nvidia-smi for this machine. Use the venv Python to run measure.py with PYTHONUTF8=1. It records freeze, isolates CUDA by UUID, probes real official input offline, and starts the single official runner only after a complete first Body UNet forward has passed the shape gate. A completed diagnostic forward intentionally exits 42. The full run output path must be unused.
3. blocking.py is a separate optional launch-blocking diagnostic for a reported asynchronous CUDA error. It cannot launch a full run. describe.py, sample_summary.py and checksums.py consolidate evidence. Use a fresh run directory or archive previous logs before retrying.
The published small/real samples are separate. CPU-side profiler dispatch events identify kernel families when specific ATen events are present. Original inputs/checkpoints and the official inference script stay outside the instrumentation directory.
